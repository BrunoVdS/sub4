## 2. What is open, in the order it was last ranked

### 2.1 `newest removal` does not name the family

The ledger census says *"newest removal: 2026-08-15T15:25:27Z · authored ·
1 row"*. It names the trigger and the count and not WHICH family lost a row.

`migration_run.rowsRemoved` is a single INTEGER added by 369. The `note` column
exists but belongs to `verifyPending` and `activateVerified`, which overwrite
it — so a breakdown written there disappears the moment the run is verified.

**Naming the family needs a migration**: a new column, or a
`migration_run_removal(runID, family, rows)` table. Plus import plumbing, the
census, and tests. Sized like 369.

Worth doing: 369 exists because *"a run deleted rows"* was invisible. *"Which
rows"* is the same argument one level down, and after 372 deleted authored data
is the sharpest risk this project has.

item, and the largest open risk.

## 4. A pattern this day found three times

369a summed three of six removal counters. 372's §12.115.6 named four of five
stores carrying an exposure. 377 found five of six persistence families.

Each was a hand-maintained list in a different file from the thing it
enumerated, and each time the fix was to read declarations rather than trust
the list. `scripts/check-invariants.py` (373) is where a rule goes once it has
caught something real; it holds four, and `test.sh` runs it before every build.

**It cannot hold the third one.** Nothing in Swift declares "this type is a
persistence family", which is why `fieldCount` is a hand-pinned number. The
count fails when the struct gains a field — and at 377 the struct had never
gained one.

## 5. And the thing that went wrong four times

374a, 374b, 374c and 375b were compile breaks shipped by an assistant with no
Swift toolchain. Three were one mistake: anchoring an edit on a substring
without reading the construct it sits inside — and in all three the file
already carried a comment describing the exact constraint being broken.

`./scripts/test.sh` caught every one in seconds and refused to call a
non-building target a pass. That is patch 325b's guard, working.

it compiles on the machine with Xcode.** Everything checkable without a
compiler still gets checked; none of it is verification of the build.
