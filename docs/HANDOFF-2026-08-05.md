## 2. What D0 closed on 5 August, patch 246

Three real gaps, none of them the one this document claimed:

1. **The frozen seed hash had drifted.** ADR §9.2 recorded 243,194 bytes /
   `e93bf5ea`; the file has been 279,078 bytes / `a4087101` since patches
   237–242. The ADR's own stated reason for recording it was that divergence be
   detectable, and it was not detected for three weeks. `PlanSeedTests` now
   fails the build on any change to the bundled seed.
2. **The seed had no provenance on the machine.** `extract_plan.py` and
   `marathon_plan_sub_4hr.html` existed nowhere under `~/Documents/Developer`.
   Now committed under `tools/` at the repository root — outside `Sub4/`, since
   synchronized groups would otherwise bundle them into the app. Decision:
   **archive, do not maintain**; running the extractor would revert patches 238
   and 242, and `tools/README.md` says so in its second paragraph.
3. **There were no fixtures at all.** `LegacyFixtures.swift` captures ten
   legacy inputs across ten damage classes. This is the direct input to the D3
   work below. Seven were found by reading the stores; the coverage test against
   `DataLifecycle` found the other three — `constants.json` and the two
   pre-split monoliths `details.json` and `streams.json`, which `DetailStore`
   still reads and which nothing has ever deleted.

Three findings fell out of writing the corpus. `AthleteStore.Cache` is
`private`, so `athlete.json` cannot be decoded by any file-level decoder until a
non-private mirror exists — a prerequisite for the quarantine patch.
`activities.json` and `constants.json` hold no `Date` at all, so they belong to
neither side of the contract's ISO-8601/numeric split. And `AthleteConstants`
has three non-optional properties with Swift default values, which the
synthesised `init(from:)` does not use — so a `constants.json` written before
any one of them existed fails to decode entirely, taking the typed maximum and
the whole resting series with it.

## 3. The four deviations to keep in mind

1. **No protected snapshot.** The migration contract item 3 requires copying
   every legacy input into a dated protected snapshot with path, byte count and
   SHA-256 *before decoding*. Never done. Two reinstalls destroyed `notes.json`,
   `weather.json`, the UserDefaults gates and HealthKit authorisation. **This is
   the most important missing piece in the project** and it is the next patch.
2. **No `migration_run` ledger.** Nothing can be `verified` or `activated`
   because no such state exists.
3. **The import reads the live stores, not the files.** A deliberate choice,
   argued in `Sub4Import`'s header — a cutover's target is what the app *shows*.
   The cost: absent, empty, corrupt and truncated input cannot be told apart,
   because no legacy byte is ever read. The corpus from patch 246 now says
   exactly what that costs, in tests.
4. **Import order is inverted** relative to the contract, which wants the plan
   and irreplaceable data first. We did activities first and the plan sixth.

## 4. Next: D3, in four patches

Do these in order. Each is device-verified before the next starts. **Renumbered
from the 4 August version, where these were 246–249; 246 went to D0.**

### Patch 247 — the manifest and the protected snapshot

- Build the manifest from `DataLifecycle.entries`, which is already the single
  source of truth for what the app writes and is already covered by tests. The
  seven `LegacyInput` cases from patch 246 are the same list, and
  `LegacyFixtureTests` asserts the two agree — so a store added without a
  fixture fails before it can be missed by a snapshot.
- For every declared path: absolute path, exists, byte count, mtime, SHA-256.
  A missing file is *recorded as missing*, never skipped.
- Copy — never move — into `snapshots/<yyyy-MM-dd-HHmmss>/`, with
  `manifest.json` beside it. File protection on the folder, same as the database
  directory.
- Surface it: last snapshot, file count, total bytes, and a "Snapshot now"
  button in Database health.

**Acceptance:** every path `DataLifecycle` declares appears in the manifest;
hashing the same file twice gives the same digest; a deliberately deleted file
shows as missing rather than vanishing from the list; the snapshot survives a
relaunch and is readable.

### Patch 248 — the `migration_run` ledger

- New migration adding `migration_run`: id, startedUTC, finishedUTC, state,
  snapshotID, appVersion, note. State CHECK in
  `pending / running / verified / activated / failed` — frozen vocabulary, held
  to a Swift enum by test, like every other vocabulary in this schema.
- The import opens a row, moves it through the states, and closes it.
- Database health shows the current state and the last run.

**Acceptance:** an import that throws leaves `failed`, not `running`; two
imports produce two rows; the state vocabulary and the enum agree.

### Patch 249 — file-level decoders and quarantine

- Read the legacy files directly, alongside (not instead of) the store-based
  import.
- **First:** a non-private mirror of `AthleteStore.Cache`. Nothing here can read
  `athlete.json` until that exists — patch 246 proved it with a test.
- Correct decoder per store. `LegacyInput.dates` already states which is which
  and the corpus proves each one; `activities.json` is the exception that stores
  no `Date`.
- Classify each input against `LegacyDamage`'s ten cases. Validate outer
  dictionary keys against the embedded `sessionUid` / `activityId` and
  quarantine mismatches rather than picking one.
- `quarantine` table plus a recovery screen listing what was held back and why.

**Acceptance:** the two tests in `LegacyFixtureTests` named
`todayEverythingBrokenLooksTheSame` and `aKeyMismatchIsInvisibleToTheDecoder`
now FAIL, and are rewritten as classifier assertions rather than restored. A
truncated fixture is reported as truncated, not empty. An absent file on a fresh
install is not an error.

### Patch 250 — the semantic verifier

- Compare the database against the stores: counts, id sets, content
  fingerprints, and a handful of *representative domain outputs* — CTL on a
  chosen day, one week's volume, one activity's splits, one weather reading.
- `migration_run` reaches `verified` only when the verifier passes, and the
  screen shows what was compared rather than a single green tick.

**Acceptance:** deliberately deleting one row from the database makes the
verifier fail and name the table; a clean run reports every comparison it made.

## 8. What this project has learned, and keeps re-learning

- **Real data beats tests.** Every serious defect in the first week of August was
  found by reading a number on the phone: the FTP endpoint that never carried
  the field, the plan whose totals needed 66 km/h on a bike, twelve details lost
  to a zero heart rate, a migration body edited after it had run while eight
  tests stayed green.
- **A number recorded in prose is not a control.** ADR §9.2 wrote down a hash so
  divergence would be detectable, and the divergence went undetected for three
  weeks. Only a test detects things.
- **Write the ADR mapping against the Swift type before writing the importer.**
  Seven for seven on finding something.
- **A green suite cannot see a schema that diverged from its migrations.** Tests
  build from source; a device holds what its history built. `sqlite_master` is
  the only witness.
- **`nonisolated` is a claim that code can run anywhere**, and it obliges
  everything it touches. Not a tidiness marker. Six instances in one week.
- **A control that reports work it did not do is worse than one that fails.**
  Five of those were fixed in one week; §12.13.2 was the sixth.
- **A stage's status must live somewhere a reader can see it.** This document
  claimed a week of finished work was outstanding because its status had to be
  reconstructed from an 86,000-byte ADR.
